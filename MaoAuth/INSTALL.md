# MaoAuth — установка прототипа

## 1. Подготовить API сайта

1. Возьми из репозитория файл `site/api/game-login.php` и загрузи его в папку `api/` на хостинге сайта.
2. В приватном `api/config.php` добавь в массив `app` параметр:
   `'game_server_secret' => 'СЛУЧАЙНЫЙ_СЕКРЕТ_НЕ_МЕНЕЕ_32_СИМВОЛОВ',`
3. Не загружай приватный `config.php` в GitHub. В репозитории теперь добавлено правило игнорирования этого файла.
4. Секрет должен совпадать с `server-secret` в конфигурации плагина.

Для генерации секрета используй менеджер паролей или криптографический генератор. Не используй пароль от базы данных.

## 2. Собрать плагин

Требуются JDK 21+ и Maven 3.9+:

```bash
cd MaoAuth
mvn clean package
```

Готовый файл: `MaoAuth/target/maoauth-0.1.0.jar`.

В репозитории настроена GitHub Actions сборка; после успешного запуска архив JAR будет доступен в Artifacts соответствующего запуска workflow.

## 3. Установить на Purpur

1. Останови сервер.
2. Скопируй JAR в `plugins/`.
3. Запусти сервер один раз, чтобы создалась папка `plugins/MaoAuth/`.
4. Открой `plugins/MaoAuth/config.yml`, задай тот же секрет и проверь URL API.
5. Перезапусти сервер.

Сначала проверь вход на тестовом сервере. Не ставь прототип на основной сервер без тестирования.

## 4. Режим offline

При `online-mode=false` UUID основан на нике. Это не является доказательством владения ником. Не открывай backend-порт напрямую, если используешь прокси; настрой Velocity modern forwarding и firewall так, чтобы к backend мог подключаться только прокси.

## Текущие ограничения

Это ранний прототип: реализован вход по MaoPickMe логину/паролю через GUI. Автоматический вход из MaoLauncher требует отдельного клиентского handshake/механизма передачи одноразового билета; он ещё не подключён. Также необходима проверка совместимости сборки с конкретной версией Purpur 26.2 и тестирование на копии сервера.
